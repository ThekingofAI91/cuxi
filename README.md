# 促膝

与人物对话的 AI 应用。荣格、阿德勒、王阳明、峰哥、张雪峰五个人物各有独立人设、知识库与界面主题(依次为纸墨 / 夜航 / 印刷 / 街头 / 直播数据台)。首页三个入口:**促膝**(与五位人物一对一,选人页按「问道 · 言必有据 / 会心 · 不设防」两种气质分组)、**争鸣**(多人物圆桌交锋)、**传奇**(用户扮主角推进剧情)。开源,Apache-2.0。

```
忠实度 8.94 / 相关性 9.75 / 口吻一致性 8.74   自建 166 题 LLM-as-Judge 五维评测
寒暄首字 ~2s / 检索端到端 ~2.4s / 重复提问 0.05s   单机 CPU 实测
pytest 514 个用例   覆盖编排 / 检索 / 状态隔离 / 异常处理
```

一次由评测驱动的修复:首轮评测王阳明忠实度 4.25,归因是传记语料缺失而非检索问题,补语料后 4.25 → 9.54。详见[评测](#评测)一节。

## 快速开始

环境要求:Python 3.10+

```bash
# 1. 安装依赖
uv sync --extra dev          # 或 pip install -e ".[dev]"

# 2. 初始化语料(解析 md/pdf → 分块 → 向量化 → 写入 ChromaDB)
python init_persona_data.py

# 3. 启动服务
python main.py               # 默认 http://localhost:8000
```

**配置模型 API**:本项目不内置任何 Key。推荐浏览器里填——启动后打开首页,首次访问弹出配置页(内置 DeepSeek / 百炼 / 智谱 / Kimi 预设,可先测试连接);无头部署用 `cp .env.example .env` 填三个变量。

启动后:对话页 `/`、API 文档 `/docs`、管理后台 `/admin`(用量与延迟瀑布 / 角色排行 / 图谱状态 / 自定义角色 / 圆桌 / 反馈,上线前设置 `MONITOR_TOKEN`)。

对话上下文默认保留最近 5 轮完整问答（`MAX_HISTORY_TURNS`），更早轮次在回答后异步合并为最多 1000 字符的滚动摘要（`HISTORY_SUMMARY_MAX_CHARS`）。历史感知检索先用 LLM 提炼最近两轮中与当前问题有关的背景，再拼接当前问题，总长最多 450 字符；无历史且问题在预算内时直接检索，摘要超时或不可用时回退当前问题。问题本身超过预算时仅压缩检索输入，回答模型仍接收完整问题。摘要调用的等待上限由 `HISTORY_QUERY_SUMMARY_TIMEOUT` 控制，默认 8 秒。

## 架构

```mermaid
flowchart TD
    User([用户]) --> UI[前端<br/>零构建 HTML + JS]
    UI -->|SSE| API[FastAPI 路由层]

    subgraph OneOnOne["一对一对话(自研 async 编排)"]
        Sup[Supervisor<br/>持有 search_library 工具]
        Tools[工具层<br/>向量 / BM25 / Cross-Encoder / GraphRAG]
        Cite[引用出处<br/>注入清单直出]
        Compress[历史压缩<br/>后台任务]
        Sup -->|调用| Tools
        Sup -->|回答定稿后| Cite
        Sup -->|后台| Compress
    end

    subgraph Roundtable["争鸣圆桌(LangGraph)"]
        Host[Host<br/>按紧迫度裁决下一位]
        Bid[投标<br/>每位角色自报意愿]
        Participants[中标者发言<br/>开口前由代码触发强检索]
        Host -->|并行分发| Bid
        Bid -->|收齐请缨| Host
        Host -->|定人| Participants
        Participants --> Host
        Host -.->|interrupt +<br/>SQLite checkpoint| Wait[挂起等用户点将]
    end

    subgraph Data["数据层"]
        Chroma[(ChromaDB)]
        SQLite[(SQLite)]
        Graph[(知识图谱 JSON)]
    end

    API --> OneOnOne
    API --> Roundtable
    Tools --> Chroma
    Tools --> Graph
    API --> SQLite

    LLM[LLM API<br/>主 / 备自动降级]
    Sup -->|流式| LLM
    Host -->|流式| LLM
    Participants -->|流式| LLM
```

两条链路的分工由控制流的形状决定:

| 维度 | 一对一 | 争鸣圆桌 |
|---|---|---|
| 编排 | 自研 asyncio,无状态图 | LangGraph,图上有环 |
| 谁决定下一步 | 模型决定查不查、查多深(工具参数 `strong`) | 每位角色自己投标,Host 按紧迫度裁决 |
| 挂起 | 不需要,请求级无状态 | `interrupt()` + SQLite checkpoint,重启可恢复 |
| 结束 | 单次回答即结束 | 全员弃权、发言配额耗尽、轮数与调用上限；允许保留分歧 |

争鸣的开场各自独立生成,只看议题、人设和本人的知识库资料。交锋轮不再由主持人猜下一位:每轮先并发问每位**还有配额、且上轮没发言**的角色「此刻有没有非说不可的话」,各自报紧迫度(1-5)和被冒犯的原话;主持人只做排序——紧迫度高者先说,平手时让最久没开口的人先说。因此"某某主动请缨"是角色自己给出的,不是主持人代写的。投标失败或超时按弃权处理,全员弃权即散场。后续发言、投标、定人和结束总结都读取完整发言记录,保留每位人物的署名、轮次和正文;发言者另有自己的开场立场可供对照。资料与记录作为引用数据传入,固定规则放在 system 消息中。每轮检索仍从原议题查询本人知识库,避免对手的说法直接引导证据召回。

发言结束不等于达成共识。主持人总结各方主张、仍存的分歧和待核查问题,仅在发言提供依据时整理观点的适用条件,不判胜负、不强行折中。独立性探针可用 `.venv/Scripts/python.exe scripts/eval_roundtable_independence.py` 检查提示词;加 `--live` 才启用实际检索和 8 次模型生成。探针用于审查顺序影响和错误观点干扰,不提供未经验证的防污染分数。实现与验证记录见[工程笔记](docs/engineering-notes.md#roundtable-independence)。

`strong` 是检索深度分档,不是开关:`true` 走完整管线出 6 条带来源,`false` 只取向量+BM25 top-3 作"模糊印象"。选择权在模型——工具描述里写清什么情况用哪档。

### 人设与文面契约外置为技能包

角色人设和传奇的叙事契约都是**内容而非逻辑**,以 Markdown 技能包放在 `data/persona_chat/skills/`:

| 文件 | 作用 |
|---|---|
| `{角色id}.md` | 角色内容的唯一来源：人设、性格特质、当前场景、世界书、对话示例、开场白、口吻要求、后历史指令 |
| `_defaults-education.md` / `_defaults-entertainment.md` | 自建角色创建时复制的口吻与后历史指令模板，使用 `{{char}}` 代入角色名 |
| `legend-narrator.md` | 传奇叙述者契约:铁律、叙事节奏、三类文面标记;含 `{{world}}` `{{state_block}}` 等占位符,由 `legend.py` 注入 |

分工原则:**技能包管"怎么做"(口径与输出格式),向量库管"说的是否有依据"(可标 n 追溯到原书章节)**——两者不能互相替代,563 万字语料塞不进任何一段说明。

角色的所有设定均从技能包读取，`characters/*.py` 只保留身份展示、分区、资源路径与采样参数。修改 Markdown 后按文件修改时间更新缓存，无需重启；分节留空就是清空该项，不再从 Python 回填。角色技能缺失或人设为空时明确报错，避免悄悄使用另一份旧设定。

自建角色的设定也保存到独立技能包，创建时从对应分区模板复制口吻与后历史指令，此后随角色独立维护。世界书使用“关键词：内容”条目，旧的“核心概念词条”分节标题继续兼容。`scripts/export_character_skills.py --check` 保留旧命令入口，只校验技能源与身份元数据，不再反向导出或覆盖内容。

## 检索管线

向量 + BM25 双通道 → RRF 融合(每类一票,类间与来源加权)→ 前 3 条免精排直通 + 其余 Cross-Encoder 精排选 3 → 注入 6 条完整原文。知识图谱按需触发:查询命中的图谱实体未被文本覆盖时,BFS 两跳子图并入证据,标注为推断。

几个有记录的取舍(完整推导见 [`docs/engineering-notes.md`](docs/engineering-notes.md)):

- **Multi-Query + HyDE 整体删除**。实测改写 3.5s+ 超预算、生成率 93% 但三轮实验测不出质量增益——删了整条链路和四个配置项。
- **索引块数 -97.4%**。扫描件 OCR 逐行碎片拼接去重后重新分块,18.8 万块 → 4,965 块,检索质量反而提升。
- **来源可信度加权**。二手解读强降权(0.25),防第三者评价冒充本人原话;代价是《被讨厌的勇气》里的流行概念排不进 top-K——这个冲突还没解掉。
- **精排分数 LRU 缓存**(2000 条,含内容指纹):重复提问精排零推理。
- **块尾续接**:按页分块导致 64% 的块断在句中,注入时用 metadata 把下一块首句补上,只写 metadata 不重建索引。

## 几个工程问题

### 寒暄不再走完整检索

用户问「你好」也走完检索全链路才调模型。把「什么时候该查」写进检索工具的描述,由模型判断,寒暄类一次 LLM 直出(首字 ~2s)。代价是模型会漏判/多判——漏判丢依据、多判多两秒,所以工具描述倾向「不确定就查」。

### 上游返回空响应

网关偶发「HTTP 200 但 content 为空」,流式挂 13 秒返回空壳。空壳视为失败立即重试(仅未推送 token 时,不会重复输出),流式加首 token 超时。单次失败代价 13s → 6s。代码:`src/core/llm.py`。

### 并发下的配置串扰

多用户并发时全局配置会串(LLM 配置放全局变量,A 用户可能用上 B 的模型)。`contextvars.ContextVar` 做请求级隔离。代价:跨线程/后台任务要显式带上下文,圆桌耗时统计因此改存 state。

### 引用出处不单独跑核查

曾经回答定稿后异步跑 verifier 逐条核查论断,前端最多等 15 秒。删掉——出处随检索 metadata 进来,注入清单直出编号对应的引用,零额外调用。

## 评测

当前 LLM-as-Judge 对五个维度分别使用 **1–5 整数分**，每一分对应一档明确标准，汇总均分保留小数。新评测默认保存到 `tests/eval_results_5point.json`；主评测、补评和分析脚本共用 `EVAL_RESULT_FILE` 配置，续跑会检查分制。

### 历史 166 题 LLM-as-Judge(五维,0-10)

以下保留原 10 分制评测结果。切换分制后的结果需按新标准重新评判，不能直接把旧分数除以二。

覆盖 5 位人物(荣格 52 / 阿德勒 40 / 王阳明 40 / 峰哥 17 / 张雪峰 17),全部产出可解析评分:

| 指标 | 得分 |
|---|---|
| 忠实度 | **8.94** |
| 回答相关性 | **9.75** |
| 上下文精确度 | **8.19** |
| 要点覆盖率 | **9.44** |
| 口吻一致性 | **8.74** |

第五维「口吻一致性」衡量说话像不像本人,与忠实度(有无事实依据)分开计分。

### 失分模式

按角色的忠实度:王阳明 9.28 / 阿德勒 8.97 / 荣格 8.94 / 张雪峰 8.53 / 峰哥 8.47。三类集中问题:语料覆盖不到时模型补训练知识(峰哥最低,语料截止 2024)、来源加权与概念覆盖的冲突(阿德勒)、术语检索精度。RAGAS 三维(53 题)作对照诊断,与 LLM-as-Judge 不能横比,原因与原始数据见 [docs/eval-report.md](docs/eval-report.md)。

### 一次评测驱动的修复

首轮评测王阳明忠实度仅 4.25。逐题查看发现检索精度与其他角色持平——是传记语料缺失,不是检索坏了。补语料重测,原 0 分题升到满分,该角色 4.25 → 9.54。这件事定了后来的方法论:**先归因,再动手;该修语料时别动检索**。

评测集 = 内置 12 题 + 扩充 154 题(带角色字段),扩充题按「词条在语料里的出现次数」筛过,语料里查不到的概念已换题。
